# sing-box-smart

`sing-box-smart` 是运行在 OpenWrt/ImmortalWrt 软路由上的 sing-box 节点监控和自动选路服务。它通过 sing-box 的 Clash API 检查节点质量，持续记录节点的成功率、延迟和失败情况，再根据分数、分层和恢复迹象决定是否切换当前策略组中的节点。

它主要解决三个问题：

1. **节点质量会变化。** 一个现在很快的节点可能随后超时，一个暂时变慢的节点也可能恢复；程序不会只根据一次测速结果做决定。
2. **所有节点都高频完整探测会浪费流量。** 当前使用的节点需要及时发现故障，优秀候选需要保持足够新鲜，普通节点则降低检查频率，同时保留恢复检查机会。
3. **人工切换难以持续观察。** 程序可以自动比较当前节点与其他可用节点，并通过 sing-box selector 执行切换；监控面板实时展示状态、分数、延迟历史和切换日志。

## 工作机制

### 1. 发现策略组和节点

程序连接配置的 sing-box Clash API，读取根策略组（默认 `proxy`）的直接成员，只选出名称符合匹配规则的 `selector` 策略组。默认匹配规则是 `PIN$`，因此 `tolink PIN`、`pei PIN` 等组会被自动发现，不需要把机场名称写死在代码中。根组没有可用成员时才使用目录扫描；`-pins` 只作为动态发现失败时的兼容回退配置。

每个策略组就是一个可切换的机场入口。用户可以在监控面板中选择策略组，程序只检查当前策略组里的节点，切换策略组时重新发现节点并开始新的启动观察阶段。策略组和节点发生重复、空名称或归属异常时会被拒绝，避免两个配置项错误地指向同一个机场。

### 2. 探测方式

真实模式调用 sing-box Clash API 的 `/proxies/{节点}/delay` 接口，使用配置的测试 URL（默认 `https://www.gstatic.com/generate_204`）。这不是 ICMP ping，也不是在程序中直接建立代理流量；延迟和成功/失败结果来自 sing-box 内核的 delay 测试。

默认探测频率如下：

| 节点类别 | 默认间隔 | 目的 |
| --- | ---: | --- |
| 当前节点 | 3 秒 | 尽快发现当前线路故障或明显变差 |
| 候选节点 | 30 秒 | 保持可切换节点的状态新鲜 |
| 普通节点 | 5 分钟 | 降低探测流量，同时定期发现变好的节点 |
| 恢复复查 | 3、6、12、20 秒 | 普通节点出现明显变好迹象后逐步确认 |

节点之间独立安排，不需要等待其他节点完成检查。全组重排时会错开到期时间，避免一次同时发起大量请求。暂停检测会取消尚未完成的探测，暂停期间不自动切换；恢复后继续按当前状态安排检查。

### 3. 分数

分数越低越好。它同时考虑延迟、成功率和失败倾向，而不是把失败伪装成一个很大的延迟：

```text
L = 延迟的指数移动平均
p = (S + 1) / (N + 2)
f = 失败率的指数移动平均
score = L / (p³ × (1 - f)³)
```

其中：

- `L` 只使用成功探测的真实延迟；最近一次延迟占比更高。
- `S` 是平滑后的成功量，`N` 是平滑后的检查量。
- `p` 是带平滑的成功概率，避免刚启动时一次成功或失败造成极端判断。
- `f` 是失败倾向；失败会降低分数表现，连续失败会让分数快速变差。
- 节点没有成功延迟时不生成伪造分数，面板显示 `—`。
- API 本身异常不会被当作节点失败，也不会更新节点分数；程序会暂停新的节点探测并重试 API 健康状态。

因此，“失败、成功、失败”会持续反映在分数中，而不是只处理连续失败。节点恢复后，新的成功结果会正常参与分数计算，但一次成功不会立刻把长期失败记录完全抹掉。

### 4. 候选层和普通层

程序不会永久写死前 10 个节点。它先按最新有效分数排序，再寻找相邻节点之间的明显分数断层。断层前是候选层，断层后是普通层；如果没有明显断层且节点较多，才使用按比例的候选数量，并把候选总数限制在最多 20 个。

这使得“候选”和“普通”之间代表实际质量差异：第 10 和第 11 名接近时不会强行制造一条界线；明显更差的节点则不会因为排名靠前一点就进入高频检查。当前节点另外标记为当前节点，但仍参与同一套分数和切换判断。

分层会随着新探测结果自动重算，节点可以在候选层和普通层之间移动：

- 普通节点变好后，成功结果先正常计分；
- 如果出现失败后低延迟成功、延迟明显下降，或分数已经接近候选边界，就安排恢复复查；
- 复查成功并重新分层后，它会进入候选层并改用候选频率；
- 普通节点不会因为一次偶然低延迟就立刻长期占用候选层。

### 5. 自动切换和恢复

自动切换由分数差决定，不由“失败两次”这类固定次数决定。当前节点分数超过最佳可用其他节点分数的 `1.4` 倍时，程序会确认候选并执行切换，再读取 sing-box 实际选择结果。

当前节点刚刚失败不会单独触发一个完全不同的评分体系；失败会先进入统一的结果、历史和分数流程。普通节点的恢复逻辑只负责在低频检查之外及时捕捉“可能变好”的节点，重点包括：

- 上一次失败，这次成功且延迟足够低；
- 本次延迟相对最近成功延迟基线明显下降；
- 分数已经接近候选边界。

恢复复查按 `3 → 6 → 12 → 20` 秒逐步放慢。复查结果仍然会计入检查次数、历史和分数；如果恢复没有被证实，节点回到相应层的正常安排。全部节点都失败时保留已有策略选择，不会随便切换到一个未知节点；节点恢复成功后再恢复正常选择流程。

### 6. 启动阶段

启动或切换策略组后，不会看到第一个完成探测的节点就立即使用。每个节点独立连续检查，程序至少观察约 10 秒，并要求所有节点都完成过一次探测，然后才比较分数并选择目标。启动阶段全部失败时不选择新节点。

评分和历史记录当前保存在内存中，重启程序后重新收集；连接配置会持久保存。

## 面板和接口

后端使用 Go，前端是嵌入式 HTML/CSS/JavaScript。面板提供：

- 策略组同步和切换；
- 当前运行状态、暂停/继续检测；
- 当前节点、候选层和普通层的区分；
- 当前分数、延迟、检查次数和最近 20 次历史；
- 失败、恢复、分层和自动切换日志；
- sing-box API 地址、根策略组和策略组匹配正则配置。

状态推送优先使用 SSE：首次连接发送完整快照，后续只发送发生变化的节点和全局字段；所有连接共享快照采样源，避免每个浏览器连接都重复读取全量状态。连接断开或长时间没有有效事件时，前端会退回轮询。历史样本带有实例和版本信息，页面会丢弃旧响应，避免重连后数据倒退。

主要 HTTP 接口见 [docs/api.md](docs/api.md)。

## OpenWrt / LuCI

仓库同时提供：

- `sing-box-smart`：后端服务；
- `luci-app-sing-box-smart`：LuCI 管理页面，可启动、停止、重启和设置开机自启动；
- LuCI 中的“打开监控面板”按钮；
- 软路由上的配置文件和 init 脚本。

LuCI 的服务控制只管理 smart 服务本身。暂停/继续检测在 smart 监控面板中完成，不会停止 sing-box 内核；smart 也不会接管未选择的策略组。

默认 OpenWrt 配置：

```text
smart 面板：      http://路由器地址:9797/
sing-box API：    http://127.0.0.1:9695
根策略组：        proxy
日志目录：        /var/log/sing-box-smart
```

真实模式示例：

```sh
go run ./cmd/sing-box-smart \
  -mode real \
  -api http://127.0.0.1:9695 \
  -root proxy \
  -test-url https://www.gstatic.com/generate_204 \
  -listen 127.0.0.1:8787 \
  -settings connection.json
```

在 OpenWrt 上，推荐通过生成的 IPK 安装；`deploy/sing-box-smart.conf` 和 `deploy/sing-box-smart.init` 是服务配置和启动脚本示例。真实模式的完整说明见 [docs/real-mode.md](docs/real-mode.md)。

## 开发和测试

```sh
make run                 # 本地模拟模式，默认 http://127.0.0.1:8787
make test                # Go 测试和竞态检测
make check               # go vet
node --test tests/*.cjs  # 前端和 LuCI 审计测试
python3 scripts/build-ipk.py
```

代码按小模块组合：探测、评分、状态、分层、恢复、调度、切换、事件推送和 HTTP 接口相互分离。组件组装集中在 `internal/app`，便于单独测试和替换真实/模拟网关。

目录说明见 [docs/architecture.md](docs/architecture.md)，当前细节和边界见 [docs/design.md](docs/design.md)。

## 已知边界

- 真实探测依赖 sing-box Clash API；程序不直接读取 sing-box 内核内部连接统计，也不使用 ICMP ping。
- 目录发现发生在启动或重新应用配置时，不会自动追踪订阅文件的后续变化。
- 评分、分层和历史不跨程序重启保存。
- API 无法访问时，程序会停止新的节点探测和自动切换，直到 API 恢复。
- 日志文件名虽然使用 `.jsonl`，当前内容是滚动文本日志，不是严格 JSONL；详细行为见设计文档。
